# 三维实景

空间页面默认打开「设计全景」，顶部可切换到原有「三维模型」。全景为设计效果图，非摄像头画面，不随真实设备开关或日夜模式改变。两种展示共用房间设备控制。全景为固定视点，三维模型采用 P-07 尺寸图外轮廓，并依照全景重建内部装修，不能用于量房或施工。

## 本地全景素材

- 来源：用户指定的[炫云分享作品「埠印贤府」](https://vr.shinewonder.com/pano/page/publik/pklimit?inf=MGMAFDMG@D@ACLDG@)，作者「喇叭|一再全案设计工作室」，于 2026-11-23 下载。仅保存该作品公开播放器使用的图片，不复制播放器代码。
- `panoramas.json` 记录来源、场景 ID、独立全景房间 ID 和现有家庭房间映射；`public/panoramas/buyin-xianfu/` 保存 60 张面图和 10 张缩略图，约 31 MB，随 Vite 构建和 Docker 镜像打包。运行时不请求炫云，无需配置第三方账号。
- 8 个房间、10 个视点：客厅 3 个，餐厅、厨房、主卧、次卧、书房、主卫、卫生间各 1 个。餐厅/厨房映射到家庭的「餐厨」，素材中的「卫生间」映射到「次卫」。入户暂无全景时明确显示空状态。
- 全景使用六面 JPG，Three.js 顺序为 `r,l,u,d,f,b`，初始相机朝 +Z；图片为发布版本，不代表设计师的最高分辨率源文件，也不包含可导出的三维几何。
- `Panorama.tsx` / `panorama-viewer.ts` 按房间加载六面图，支持拖动、触摸、键盘环顾、缩放、重置和失败重试。旧请求不会覆盖新房间，切换和卸载释放纹理。窄屏可直接使用顶部房间/视点选择器。
- 三维模型首次选择时才创建；切回全景暂停模型渲染，再切回保留相机和当前会话导入的 GLB。离开 VR 页面仍会释放模型，符合原有会话内导入行为。
- 使用 `npm test --prefix frontend` 验证全部本地图片、房间映射、异步切房、失败重试和资源清理。

## 全景参考三维模型

当前默认模型由 `models/build_panorama_home.py` 生成，输出可编辑的 `models/panorama-home.blend` 和浏览器使用的 `models/panorama-home.glb`。它以用户提供的 [P-07 家具尺寸图](../../../docs/reference/floor-plan-p07.jpg) 为外轮廓和尺度依据，以本地全景为装修与家具依据。图纸与全景内部方案并不完全一致，房间分隔与家具摆放仍属估算。

- `design-model.json` 是本模型的房间、墙体、家具占地、相机定位、外轮廓多边形和估算说明的共同来源。米为单位，Three.js 坐标 X 向右、Y 向上、Z 向下；Blender 使用 `(x, -z, height)`，导出 glTF 后坐标一致。
- 外轮廓主要标注：总宽 12.91 m、最大进深 7.53 m，右侧底边相对左上原点为 Z=6.14 m，上侧凹口 X=5.94 m、Z=0.89 m，左下翼宽 5.74 m。入户及柜体外缘未单独标注的进深按图像比例追踪（约 Z=5.80/6.32 m）。多边形外轮廓投影约 81.0 m²，含墙体，不能等同于建筑面积或产权面积。
- 家具造型和饰面参考全景；图中没有明确对应的房间分隔、层高、家具尺度与连接关系继续标注估算。外墙、地面、天花、小地图与人物边界统一使用凹形 footprint，不得补成矩形或用整屋非等比缩放扭曲家具。
- `plan.ts` 从该数据生成导航与碰撞；`SpaceMap.tsx` 使用相同墙体和家具占地绘制小地图。主卧、次卧、书房、餐厅、厨房及两卫均有独立定位，餐厅和厨房的设备仍映射到「餐厨」。
- `scene.ts` 加载完整 GLB，等待期间显示简化布局，失败显示错误和重试。模型 mesh 的 `extras.presentation` 区分 `wall`、`ceiling`、`overhead`、`floor`、`furniture`：总览按 1.22 m 剖切墙体、隐藏顶面及高位构件，家具保留完整高度；进入房间或漫游恢复完整空间。
- 模型使用 `Glow_` 前缀材质控制预览灯带，照明开关仅影响三维预览，不绑定真实设备。日夜切换同样仅影响三维预览。
- GLB 导入仍仅在当前浏览器会话读取，不上传、不保存；上限 100 MB，要求贴图内嵌，未配置 Draco、Meshopt 和 KTX2 解码。自定义模型按参考模型最大平面边缩放用于预览，未自动生成房间定位，不能把显示尺寸当作原始尺寸。
- 旧 `millwork` / `furnishings` 的 JSON、构建脚本、BLEND 和 GLB 保留为历史源资产，当前网页不再加载这些旧模型。后续补充房间分隔、层高与家具尺寸时，应调整新模型数据与生成脚本，再重新导出。

重建：

```bash
blender -b -t 4 --python-exit-code 1 --python frontend/src/vr/models/build_panorama_home.py
```

验证：`npm test --prefix frontend` 检查图纸总尺寸与凹口、估算标记、素材覆盖、视点不落入障碍、从入口到全部房间的行走连通性，以及 GLB 分类标签。`npm run build --prefix frontend` 验证类型和打包；后端基线为 `npm test --prefix backend`。

## 界面文案

项目/设计师来源、尺寸依据和估算说明保留在本文与模型元数据，不作为页面常驻提示展示。空间页只显示房间、模式、操作控件和必要的加载/错误/空状态；移除键鼠说明及面积/跨度说明，避免将参考模型解释成测量结果。全景图片仍作为设计全景呈现，设备真实状态保持独立显示。
