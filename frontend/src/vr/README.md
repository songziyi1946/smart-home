# 三维实景

空间页面默认打开「三维空间」，以立体剖切户型总览展示家庭；顶部可切换「设计全景」。点击模型区域、房间标签或房间列表后，相机平滑旋转并放大到该房间，侧栏或移动端抽屉显示对应设备；「全屋总览」恢复全屋视角。没有第一人称漫游、行走按键或人物定位。全景为固定视点的设计效果图，非摄像头画面，不随真实设备开关或日夜模式改变。模型采用 P-07 尺寸图外轮廓，并依照全景重建内部装修，不能用于量房或施工。

## 本地全景素材

- 来源：用户指定的[炫云分享作品「埠印贤府」](https://vr.shinewonder.com/pano/page/publik/pklimit?inf=MGMAFDMG@D@ACLDG@)，作者「喇叭|一再全案设计工作室」，于 2026-11-23 下载。仅保存该作品公开播放器使用的图片，不复制播放器代码。
- `panoramas.json` 记录来源、场景 ID、独立全景房间 ID 和现有家庭房间映射；`public/panoramas/buyin-xianfu/` 保存 60 张面图和 10 张缩略图，约 31 MB，随 Vite 构建和 Docker 镜像打包。运行时不请求炫云，无需配置第三方账号。
- 8 个房间、10 个视点：客厅 3 个，餐厅、厨房、主卧、次卧、书房、主卫、卫生间各 1 个。餐厅/厨房映射到家庭的「餐厨」，素材中的「卫生间」映射到「次卫」。入户暂无全景时明确显示空状态。
- 全景使用六面 JPG，Three.js 顺序为 `r,l,u,d,f,b`，初始相机朝 +Z；图片为发布版本，不代表设计师的最高分辨率源文件，也不包含可导出的三维几何。
- `Panorama.tsx` / `panorama-viewer.ts` 按房间加载六面图，支持拖动、触摸、键盘环顾、缩放、重置和失败重试。旧请求不会覆盖新房间，切换和卸载释放纹理。窄屏可直接使用顶部房间选择器。
- 三维模型按所选保存版本创建；切回全景暂停渲染，再切回保留相机。切换模型/版本会取消旧资源加载并重建视图，同时清除房间和设备面板。离开页面释放渲染资源，已保存模型仍留在服务器。
- 使用 `npm test --prefix frontend` 验证全部本地图片、房间映射、异步切房、失败重试和资源清理。

## 全景参考三维模型

当前默认模型由 `models/build_panorama_home.py` 生成，输出可编辑的 `models/panorama-home.blend` 和浏览器使用的 `models/panorama-home.glb`。它以用户提供的 [P-07 家具尺寸图](../../../docs/reference/floor-plan-p07.jpg) 为外轮廓和尺度依据，以本地全景为装修与家具依据。图纸与全景内部方案并不完全一致，房间分隔与家具摆放仍属估算。

- `design-model.json` 是本模型的房间、墙体、家具占地、相机定位、外轮廓多边形和估算说明的共同来源。米为单位，Three.js 坐标 X 向右、Y 向上、Z 向下；Blender 使用 `(x, -z, height)`，导出 glTF 后坐标一致。
- 外轮廓主要标注：总宽 12.91 m、最大进深 7.53 m，右侧底边相对左上原点为 Z=6.14 m，上侧凹口 X=5.94 m、Z=0.89 m，左下翼宽 5.74 m。入户及柜体外缘未单独标注的进深按图像比例追踪（约 Z=5.80/6.32 m）。多边形外轮廓投影约 81.0 m²，含墙体，不能等同于建筑面积或产权面积。
- 家具造型和饰面参考全景；图中没有明确对应的房间分隔、层高、家具尺度与连接关系继续标注估算。外墙、地面、天花、小地图与人物边界统一使用凹形 footprint，不得补成矩形或用整屋非等比缩放扭曲家具。
- `plan.ts` 保留同源户型、房间区域与历史碰撞校验；`SpaceMap.tsx` 使用相同墙体和家具占地绘制房间导航。`viewer.ts` 只使用正交相机，点击区域/标签后平滑旋转并按房间大小和屏幕比例取景，支持拖动旋转、缩放、全屋回退及 reduced-motion；拖动和多指手势不会触发房间选择。
- `scene.ts` 加载完整 GLB，等待期间显示简化布局，失败显示错误和重试。模型 mesh 的 `extras.presentation` 区分 `wall`、`ceiling`、`overhead`、`floor`、`furniture`：始终按 1.22 m 剖切墙体、隐藏顶面及高位构件，家具保留完整高度；聚焦房间仍保持立体总览视角。
- `room-state.ts` 通过明确的模型房间 ID → 业务 roomId 映射聚合现有 SSE 数据，不按可修改的房间显示名猜测归属。兼容旧 room 编码，餐厨共享分组明确标注，独立餐厅和厨房分组不混用。
- 房间标签和侧栏显示运行/离线数量、来源、环境读数和活动情况；缺失/离线遥测显示暂无数据，模拟和断线缓存都有标识。设备详情复用 capability 控制面板，房间选择只改变视图。
- 房间照明仅根据已绑定房间中在线、已知开关状态的 brightness 灯具提供示意反馈；未知/离线或餐厨共享分组不推测照明。没有设备坐标时不放置虚构设备点位。未绑定具体设备的 `Glow_` 装饰灯带不再默认发光，日夜配色只影响基础展示照明。
- GLB 在独立预览通过后由管理员选择保存为新模型或更新当前模型。单文件上限 30 MiB，要求资源内嵌，未配置 Draco、Meshopt 和 KTX2 解码。上传时自动读取包围盒，宽度校准等比调整其他尺寸；房间范围在等比缩放、包围盒平移至原点后的 X/Z 坐标系中设置。未配置空间范围的房间仍可从列表查看绑定设备，但不会生成虚构位置标签。
- 旧 `millwork` / `furnishings` 的 JSON、构建脚本、BLEND 和 GLB 保留为历史源资产，当前网页不再加载这些旧模型。后续补充房间分隔、层高与家具尺寸时，应调整新模型数据与生成脚本，再重新导出。

重建：

```bash
blender -b -t 4 --python-exit-code 1 --python frontend/src/vr/models/build_panorama_home.py
```

验证：`npm test --prefix frontend` 检查图纸总尺寸与凹口、估算标记、素材覆盖、历史视点与碰撞连通性、GLB 分类标签、房间设备隔离、缺失/离线/模拟读数及拖动防误选。`npm run build --prefix frontend` 验证类型和打包；后端基线为 `npm test --prefix backend`。

## 界面文案

项目/设计师来源、尺寸依据和估算说明保留在本文与模型元数据，不作为页面常驻提示展示。空间页只显示房间、模式、操作控件和必要的加载/错误/空状态；移除键鼠说明及面积/跨度说明，避免将参考模型解释成测量结果。全景图片仍作为设计全景呈现，设备真实状态保持独立显示。

## 保存模型与版本

- `ModelManager.tsx` 负责草稿、独立预览、房间范围及绑定编辑；`model-library.ts` 调用模型接口，管理响应不覆盖设备 SSE 数据。
- `/api/models` 提供目录与新建，`/:id/versions` 追加版本，`/:id/restore` 指向历史版本，`/default` 设置家庭默认模型，`/assets/:id` 认证读取 GLB。管理员可写、成员只读；访客不访问保存模型接口，仍显示内置空间及原有受限设备数据。
- 模型、版本的房间 ID 与家庭业务 roomId 分离；每个版本保存显式 `deviceRoomIds` 和可选 `panoramaSceneId`。新模型初始为空绑定，不按同名房间猜测设备。关联全景目前来自已接入的本地素材。
- 内置模型种子位于 `packages/contracts/builtin-space-model.json`，几何和定位必须与 `design-model.json` 一致。内置几何只允许修改名称/绑定；替换 GLB 会清除旧房间范围，要求重新定位。
- 目录及二进制资源存于 SQLite 独立加密表，独立 revision 处理并发，保存失败不切换当前版本；维护备份/恢复包含模型与资源。旧备份没有模型字段时仍可恢复。
- 当前限制为 20 个模型、每模型 20 个版本、GLB 资源合计 100 MiB。切换模型只改变展示，不执行设备命令；刷新默认打开家庭默认模型。
- `ModelGenerator.tsx` 支持个人 AI 识别户型与装修、后台任务恢复、方案校正、局部家具调整和显式发布；普通 GLB 上传仍是独立入口，不冒充 AI 识图。


## 户型与装修生成工作流

- `packages/contracts/model-generation.ts` 定义方案：米为单位，X向右、Z向下；家具 x/z 是中心，rotation 是绕 Three.js +Y 的角度（平面图 SVG 使用负角度）；门窗 offset 沿墙from→to，bottom距地。
- `backend/domain/model-generation/schema.mjs` 校验尺寸、凹轮廓、墙体开口、家具房间范围、图片尺寸与关联。AI输出仅解析为JSON，不执行代码、路径或脚本。
- `source-import.mjs` 读取炫云公开分享的权限状态、场景清单和六面图，使用校验后的公网DNS固定IP下载。`needPassword=2`是密码保护；1是该公开来源的非密码状态。只存必要图像与房间信息，不保存作者联系方式等播放器无关数据。
- `service.mjs` + `repository.mjs` + `/api/model-generation` 管理个人草稿和后台任务。任务不进入设备SSE；前端只在运行时查询任务进度。退出页面不会自动再次发起识别，重启将运行中的任务标为interrupted。撤销用户权限和删除个人连接会取消相应在途调用。
- `geometry.mjs` 纯Node生成GLB，无新增运行依赖或Blender要求。用耳切三角化保留凹形轮廓、墙段开口及家具组合部件，PNG程序纹理内嵌；generated版本按原始米坐标显示，不应用普通外来GLB的包围盒重定位/缩放。
- `ModelGenerator.tsx` 同步平面图/数字编辑与独立剖切预览。保存校正不调用AI；局部AI调整必须显式选房间，服务端比较其余房间/布局并拒绝越界改动。模型预览按任务版本缓存，过期响应不覆盖新编辑。
- 发布经验证后调用模型库的原子保存，模型版本持有plan、sourceId和panoramas；草稿来源图片只有本人可读，发布后已引用的来源图片允许家庭成员读取。本人原户型图不随发布共享；复制已发布模型到个人草稿不会复制原作者AI连接或原户型图。
- 导入的六面图使用认证图片接口；只有单张参考图时显示参考图，不伪装成360°全景。切换模型切换其来源，不能按相同scene ID回退到另一套内置素材。
- 真实识图需用户自己的可看图Responses兼容服务和API Key。`outputs/qa/generated-geometry-reference.*` 是基于P07的受控可视夹具，明确不是付费AI识图结果，不作为识图准确率证明。
