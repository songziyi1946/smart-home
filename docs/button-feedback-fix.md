# 按钮状态反馈修复（2026-11-17）

## 根因与可重复证据

开发服务器 `/api` 的 `proxyTimeout: 5000` 同样作用于 `/api/events`，而后端 SSE 心跳间隔为15秒。空闲超过5秒后，代理中止上游请求，但未结束已经返回响应头的浏览器响应。浏览器仍认为连接正常，只保留首次快照。命令已经保存到后端，前端因拿不到后续快照而保持旧按钮；刷新重新取得快照后才显示结果。

隔离实验同时订阅直连后端3197和开发代理8001，等待6.5秒再关闭 Mock 灯光：命令 HTTP 200；直连收到第2帧且 power=false；代理仍仅1帧、power=true，且没有结束或报错。这复现了用户问题。

此前的直接后端与模拟器回归没有覆盖此开发代理路径，这是本次补齐的测试缺口。

## 修改

- `/api/events` 使用专用长连接代理，不使用短请求超时。
- 上游中止/错误时关闭浏览器响应；浏览器关闭时释放上游订阅，避免静默失联和连接泄漏。
- 普通 `/api` 保留5秒超时和原 Host 转发策略。
- 不改变设备模型、Provider、API、SSE 帧格式、鉴权、访客过滤或 UI 数据源；没有增加轮询，也没有用请求响应假装设备已反馈。
